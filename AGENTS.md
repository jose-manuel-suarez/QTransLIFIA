# QTransLIFIA — Contexto persistente

> Este archivo se carga automáticamente en cada sesión del agente. Equivale a `MUSE.md` (Claude), `.cursor/rules` (Cursor) o `AGENTS.md` (Codex/opencode). Si tu herramienta usa otro nombre, duplica este archivo como `MUSE.md`.

## Qué es
Traductor de circuitos cuánticos de formato **Quirk** (`https://algassert.com/quirk#circuit=...`) a **OpenQASM** (versiones 2.0 y 3.0, por defecto 3.0) como lenguaje pivote y, desde allí, a ecosistemas como IBM Qiskit, AWS Braket y Xanadu PennyLane.

## API de librería: `translate_circuit(payload)`
Función core de `qtrans/core.py`: recibe un payload JSON (dict o cadena) y devuelve `{"input": <eco normalizado>, "output": ...}` (refleja las carpetas `input/`→`output/`). Constantes del contrato `_TRANSLATE_*` (`_TRANSLATE_TOP_KEYS:596`), helpers `_unknown_keys`/`_resolve_circuit_url`/`_zx_calculus_result:645`/`_require_keys`/`_validated_bool`/`_validated_int`/`_validated_provider`/`_normalize_translate_input:733`, etapas opcionales (`qiskit_utils.image_qasm_base64`/`image_composer_base64`, `quirk_utils.image_quirk_base64`/`comparison_markdown`), `_translate_circuit_entry:847`, `translate_circuit:957`. El conteo de compuertas usa `qasm_utils.qasm_gate_summary:206`.
- **Entrada** (`input`, única clave permitida del payload): exactamente uno de `url` | `json` | `circuits` (lote: lista de `{name?, url|json, offset?}`); más `offset`, `qasm_version` ('2.0'|'3.0'), `provider` (**str con un único proveedor**; alias canónicos `qiskit`/`ibm`, `braket`/`aws`, `pennylane`/`xanadu`; una lista o varios separados por comas → `ValueError`), `shots`, `preserve_custom_gates`, `zx: {enabled, time, timeout}`, `images: {quirk, qasm, composer, capture_timeout}`, `comparison`, `return_circuit` (bool, default false; **se admite en circuito único y en lote**; en lote cada objeto de `output` trae su propio `circuits`).
- **Salida** (`output`): dict si es único, **lista** de dicts si es lote. Claves por circuito: `qasm` (`code`, `version`, `lines`, y `gates.custom`/`gates.native` = `{count, names}` únicos ordenados; el conteo se hace sobre el QASM 3.0 previo a bajar a 2.0, para que sea estable), `migrated_code` (dict con **una sola** clave `<PROVIDER_DIRECTORY>_code`, p. ej. `ibm_qiskit_code`/`aws_braket_code`/`xanadu_pennylane_code`), `circuits` (null por defecto; con `return_circuit=true` → `{proveedor: objeto nativo ya cargado}` — qiskit `QuantumCircuit` / braket `Circuit` / pennylane `QNode` — vía `provider_utils.load_provider_circuit` sobre `qasm.code`; si la carga de un proveedor falla, su valor es null y el detalle va a `errors` con stage `circuits.<proveedor>`. **Objetos vivos: con ellos la respuesta NO es JSON-serializable**), `zx_calculus_result` ('equivalente'|'no-equivalente'|'no-comprobado'; null si `zx.enabled=false`), `circuit_info` (n_qubits, n_cols, gates), `img` ({quirk,qasm,composer} en base64 PNG; quirk = Selenium, off por defecto), `comparison_doc` (Markdown inline), `errors` ([{stage,message}] de etapas opcionales fallidas; nunca tumban la traducción). **En modo lote cada objeto incluye además `name`; el circuito único no lleva `name`.**
- Claves no solicitadas = siempre presentes con `null`. Payload inválido (claves desconocidas, faltantes, mal tipadas, fuera de rango) → `ValueError`; la traducción/migración propaga sus excepciones. Tests: `test/test_translate.py` (ejecutar con `unittest discover`; el import como `test.test_translate` choca con la stdlib `test`). Ejemplo imprimible: `test/test_translate_lib.py`.

## Reglas de traducción
- `offset` desplaza todos los índices `q[i+offset]`; `n = max(_column_extent(col))+offset` (el extent cuenta la altura de custom gates y de las QFT nativas).
- `•`+`X`/`Z`/`Y` → `ctrl @ x`/`ctrl @ z`/`ctrl @ y` (1 control; con 2 controles se emite `ctrl @ ctrl @ x …`, la convención que usa el propio `stdgates.inc` de Qiskit para `ccx`), `Swap` → `swap`. `X^½` etc → `rx`/`ry`/`p`.
- **X/Y Probes de Quirk (controles de eje X/Y)**: ids `⊖` (X-Axis Control), `⊕` (X-Axis Anti-Control), `(/)` (Y-Axis Control), `⊗` (Y-Axis Anti-Control), tabulados en `_CONTROL_GATES` con su *setup*/*cleanup* (X: `h`/`h`; Y: `rx(pi/2)`/`rx(-pi/2)`) y su negación (anti-control: `x` antes y después de la operación). En Quirk el mask se evalúa **sobre el estado tras el setup** y el estado "ON" de un control de eje X/Y es el autovector de eigenvalor −1 (`|−⟩` para X, `|−i⟩` para Y); el anti-control dispara con el eigenvalor +1 (`|+⟩`, `|+i⟩`). La traducción emite `setup → ctrl @ <gate> → cleanup` (OpenQASM 3.0). En ZX se expande con `_zx_control_matrix` (setup + negación `NOT` + operación controlada + cleanup).
- **Post-selecciones nativas de Quirk**: ids `|+⟩⟨+|`, `|-⟩⟨-|` (guion ASCII, no `−`), `|X⟩⟨X|`, `|/⟩⟨/|`; tabla `_POSTSELECT_GATES`. La base Y se mide con `sdg` y luego `h` (el orden inverso mediría la base X y no distinguiría `|+i⟩` de `|−i⟩`). No son unitarias: la traducción las emite como rotación + `ps[i] = measure q[i];` y la etapa ZX devuelve `no-comprobado`. Como el mismo qubit se mide dos veces (`ps[i]` y `c[i]`), **Braket** necesita una salvedad: su parser nativo rechaza ese QASM (*cannot apply instruction to measured qubits*) y `_braket_python_source` (`qtrans/utils/braket_utils.py`) descarta la medición repetida emitiendo **una sola** `circuit.measure([q])` por qubit (el generador difiere todas las mediciones al final, así que el valor es el mismo); al cargar, el fallo nativo cae en el respaldo por script.
- Sondas de regresión de los X/Y Probes y de las post-selecciones: `input/xy_probes_gates_algorithms.json` (24 sondas: 4 controles + 4 post-selecciones × {2, 4, 6} qubits; cada par control/objetivo alterna entre un control que dispara y otro que no, y todas son deterministas) y `test/test_xy_probes.py`.
- Campo `gates` en la URL:
  - `{"id":"~rvcr","name":"MultiX","circuit":{"cols":[["•","•","X","•"]]}}` → expandible. Mapa por `id` y `name`, sufijo `:k` para gates multi-columna (`~abc:1`). Soporta anidamiento (profundidad ≤10).
  - `{"id":"~edqr","name":"mia","matrix":[…]}` → **matrix** (unitaria2×2 o 4×4): `_matrix_gate_body_lines` encadena (1) operación única si el `name` tiene forma `op(args)` de stdgates o la matriz es una fase conocida/diagonal (`{{1,0},{0,z}}` → `p(phase(z))`); si no, (2) fallback unitario `_unitary_matrix_body`: proyecta a la unitaria más cercana (SVD, tolerancia 1e-6), **2×2 → `p`+ZYZ** (`_euler_matrix_body`: `e^{i·g}rz·ry·rz` con `g=phase(det)/2`, misma fórmula que `_zx_decompose_unitary`; la fase global se materializa con la identidad `e^{i·g}·I = p(2g)·rz(−2g)`, porque `p` solo es fase *relativa*) y **4×4 → KAK de 2 qubits** (`_two_qubit_kak_body`: `transpile` de Qiskit a `['u','cx']`, cada `u` se emite como la `U` intrínseca de OpenQASM 3 — stdgates no define `u` minúscula y el parser de Qiskit la rechaza — y la fase global con `p(2φ)·rz(−2φ)`). Convención: wire superior de Quirk = bit menos significativo = qubit 0 de Qiskit = letra `a` (sin invertir qubits; confirmado en el código de Quirk: `src/circuit/KetShaderUtil.js` (`_ketgen_step = 1 << ctx.row`) y `src/circuit/GateShaders.js` (`multiQubitOperationMaker`) ⇒ la matriz de una gate custom es little-endian **dentro del bloque**, igual que las gates nativas). No unitaria de dim 2/4 sin `name` aprovechable → `ValueError` accionable. Verificación: `test/test_qtrans.py` + `test/test_matrix_customs.py` (las 8 matrices del circuito `1. complex_customs` de `input/custom_gates_algorithms.json` —antes `39. complex_customs` en `popular_algorithms.json`— reproducen la matriz de la URL con residuo ≤ 5e-8, que es el propio redondeo de 7 dígitos con que Quirk las almacena) + `test/test_matrix_equivalence.py` (**barrida exhaustiva**: recorre todas las baterías de `input/`, valida todas las compuertas con `matrix` comparando la unitaria de la declaración `gate` emitida contra la matriz de la URL, **exacta incluida fase global** con tolerancia 1e-6; corpus actual: 62 compuertas — 44 en `popular_algorithms.json`, 2 en `main_algorithms.json` y 16 en `custom_gates_algorithms.json`; los conteos canónicos fijados son 44/2 y las baterías adicionales se barren sin fijar número; peor residuo: 4.927e-08 en `mia`) + corrida `.env` (39/39, `qasm3.loads`/`qasm2.loads` y scripts migrados OK). Ojo: la etapa ZX no representa matrices 4×4 (`Matriz no soportada en el grafo ZX (se esperaba 2x2)`); un circuito que use una (`mia`, `4x4`) queda `no-comprobado`/NO COMPARABLES, no genera SVG ZX y suma 1 error de etapa (por eso la corrida de `custom_gates_algorithms.json` sale con exit code 1 aunque los 2 objetos se traduzcan correctamente).
- URLs Quirk requieren JSON estricto con `"` dobles; para `href` usar `encode_quirk_url`.
- Versión: `quirk_to_qasm(url, offset, qasm_version='3.0')` acepta `'2.0'`/`'3.0'`; `'2.0'` transpila vía Qiskit a `u1/u2/u3/cx`. La celda de generación y las celdas de migración leen `QASM_VERSION` desde `.env` (`QTRANS_QASM_VERSION`, default `'3.0'`) con `load_dotenv()`; la celda de generación escribe `_v2.0.txt`/`_v3.0.txt` y las celdas posteriores quitan el sufijo con `strip_qasm_version`.
- Celdas de migración (sección «Migración de circuitos a ecosistemas / lenguajes concretos») = **dos celdas**:
  1. **Carga** — `cargar_circuito_qasm(qasm_str, provider, qasm_version, shots, preserve_custom_gates, native=True)` (`qtrans/utils/provider_utils.py:183`) hace el `loads()` por proveedor y deja `circuitos_cargados[provider][nombre]`. Filtran estrictamente `path.name.endswith(QASM_VERSION_SUFFIX + ".txt")`; si la corrida actual no tiene `algorithms_qasm` usan (con aviso) el run más reciente que sí lo tenga, y si no hay ninguno fallan con un error accionable (hay que correr la celda de generación de OpenQASM). Comportamiento por proveedor: **qiskit** → parser nativo (`qasm2.loads`/`qasm3.loads` por cabecera, 100 % de los archivos); **braket** → `Circuit.from_ir` nativo (quitando `include "stdgates.inc"`) con respaldo automático porque no conoce la puerta `p` (~36/53); **pennylane** → **siempre** vía script migrado (`provider_python_source`+`exec` → `QNode`), porque `qml.from_qasm` exige `pennylane-qiskit` y `qml.from_qasm3` no acepta `qreg` indexados. Tipos uniformes por proveedor: `QuantumCircuit` / `Circuit` / `QNode`.
  2. **Generación** — para cada proveedor **cargado** llama `provider_python_source(...)`, hace `compile()` y escribe `output/run_*/migrated_circuits/<subcarpeta>/<nombre>.py`, donde `<subcarpeta>` sale de `PROVIDER_DIRECTORY` (`ibm_qiskit` / `aws_braket` / `xanadu_pennylane`).
  - Proveedores: `providers_from_env()` lee **`QTRANS_TARGET_PROVIDERS`** (única variable; valores canónicos `qiskit`, `pennylane`, `braket`, con alias `ibm`, `aws`, `xanadu`), default `qiskit`; `QTRANS_PROVIDERS` quedó obsoleta: se ignora y sólo emite un `UserWarning`. Ambas celdas leen además `QASM_VERSION` (`QTRANS_QASM_VERSION`, default `'3.0'`; `ValueError` si no es `'2.0'|'3.0'`), `QTRANS_SHOTS` y `QTRANS_PRESERVE_CUSTOM_GATES` con `load_dotenv()`.
  - La celda de IBM Composer usa `migrated_circuits/ibm_qiskit` (con respaldo al nombre legado `qiskit`); las celdas de imágenes/comparación definen su propia `load_qasm_circuit(text)` local (dispatch por cabecera `OPENQASM 2.0` → `QuantumCircuit.from_qasm_str`, `3.0` → `qasm3.loads`, fallback). No usar `qasm3.loads` directo sobre `_v2.0.txt` (falla con `QASM3ImporterError: '2,0: non-stdgates imports not currently supported'`).
- Puertas en los generadores de migración (`qtrans/utils/qiskit_utils.py`, `qtrans/utils/braket_utils.py`, `qtrans/utils/pennylane_utils.py`): `u1/u2/u3` (u2 lleva 2 params φ,λ: `lam = parameters[2] if name=="u3" else (parameters[1] if name=="u2" else parameters[0])`); ángulos fijos `rx_*/ry_*/rz_*` y fases fijas `cp_*/cu1_*` (incl. fracciones `_pi_`, p. ej. `cU_pi_2`, `cp_7_pi_8`) vía `_angle_to_expr` (emite `math.pi/2`, `3*math.pi/4`, …, definido en `qasm_utils.py:142`); Qiskit mapea `u1/u2/u3` a puertas nativas con `_native_gate_for_u` (h/x/y/z/s/sdg/t/tdg/sx/id) para no emitir `circuit.u(...)` en gates estándar, y usa `PhaseGate`/`UGate` (imports dinámicos `gate_imports` from `qiskit.circuit.library`) para `.control(k)`.
- Utilidades auxiliares (sección «Funcionalidades Auxiliares», ahora en `notebooks/QTrans_utils.ipynb`, separada de `QTrans.ipynb` por prolijidad): una celda define `json_algorithm` (registro con `desc`/`url`/`offset`) y la siguiente **genera, muestra un enlace clicable (`ABRIR CIRCUITO EN QUIRK`) y retorna** `url_quirk_percent_coded = encode_quirk_url(json_algorithm["url"])` (URL percent-encoded visualizable en Quirk; es la que consume la celda inversa). Las utilidades `mostrar_url_quirk(url)`/`formatear_url_quirk(url)`/`limpiar_url_quirk(url)`/`validar_url_quirk(url)` viven en una **celda aparte** debajo de la generadora — recibe **directamente la URL cruda** de Quirk (con `circuit=<JSON>`, p.ej. `url_quirk`) aunque venga **mal formateada** (con `\` y `\"` sobrantes al pegar el JSON): `limpiar_url_quirk` delega en `normalize_quirk_url` (`qtrans/utils/url_utils.py`), que quita comillas externas, recorta desde `https://` y **re-serializa el JSON del circuito interpretando los escapes `\uXXXX`** (si se borran los backslashes a ciegas, `Z^-\u00bd` queda `Z^-u00bd` y Quirk lo pinta como "parse error"); luego `encode_quirk_url` percent-encodea para que renderice en algassert.com/quirk. Devuelve/muestra un enlace `<a ...>Abrir en Quirk</a>` y valida round-trip (`parse_quirk_url` + `quirk_circuit_info` + `quirk_to_qasm`). En el JSON el `•` es U+2022 real. La celda inversa (`url_quirk_a_json_register`) reconstruye el registro de `/input` a partir de la URL.
- `qasm_to_zx_graph` admite gates con parámetros `rx/ry/rz/p/u1/u2/u3/u` y declaraciones `qreg` (QASM 2.0) o `qubit` (QASM 3.0).
- **QFT nativa de Quirk**: token `QFTn` / `QFTn†` (daga como sufijo; también se tolera prefijo `†QFTn`), regex `_QFT_TOKEN_RE` (`qtrans/utils/quirk_utils.py:123`). **En Quirk el id canónico de la inversa es `QFT†n`** (`setSerializedId("QFT†" + span)` en `FourierTransformGates.js`); las variantes `QFTn†`/`QFT^†n` no existen allí y Quirk las pinta como compuerta "parse error". `canonicalize_quirk_url` (`qtrans/utils/url_utils.py`) reescribe esas variantes a `QFT†n` y se aplica en `capture_quirk_circuit` y en `encode_quirk_url`; `input/qft_algorithms.json` usa la forma canónica. Regresión: `test/test_qft_canonical.py`. Se emite **siempre** como declaración `gate QFTn a,b,c {…}` (H + `cp(pi/2**k)` + `swap`, descomposición estándar con swaps, ≡ DFT en convención little-endian de Qiskit) y nombre inverso `QFTn_dg`; el sitio de uso es `QFTn q[i],…` (soporta `ctrl @ QFTn …`). `n` se calcula con `_column_extent`. En ZX se expande con `_zx_append_qft`.
- **`preserve_custom_gates`**: `provider_python_source(qasm, provider, qasm_version, shots, preserve_custom_gates=False)` y los tres generadores lo aceptan. `true` → cada compuerta custom/nativa (incl. `QFTn`, `cu1_*`, `cU*`) se define **una sola vez** como función local (`def nombre(circuit, w0, w1…)` en Qiskit/Braket, sin `circuit` en PennyLane) y se llama en su lugar; `false` → se expande en línea. `_unquote_parameters` quita las comillas que `!r` añade alrededor de los placeholders `wN`. En `qtrans/core.py`: `QTRANS_PRESERVE_CUSTOM_GATES`/`DEFAULT_PRESERVE_CUSTOM_GATES`, param `preserve_custom_gates` en `run_pipeline`/`provider_utils.generate_provider_files`, CLI `--preserve-custom-gates`/`--no-preserve-custom-gates` y clave en el resumen.

## `quirk_circuit_info(url)`
Retorna `{n_qubits, n_cols, gates, custom_gates, custom_gate_ids, custom_gate_names, n_custom_gates, custom_gates_gates, custom_gates_info}`. `n_qubits` es efectivo (incluye altura de gates usados).

## Pipeline CLI (`python -m qtrans` / script `qtrans`)
- `--input-mode {batch,algorithm}` (default `QTRANS_INPUT_MODE`): `algorithm` exige `--input-file` y prohíbe `--input-files`; `batch` prohíbe `--input-file` **no vacío** — `--input-file ""` (o `QTRANS_INPUT_FILE=`) se normaliza a `None` y, junto con `--input-files` vacío/omiso (`nargs="*"`, también acepta `--input-files` sin valores y entradas en blanco que se filtran), el modo batch procesa **todos los `*.json` (nivel superior) de `--input-dir`**; si `--input-files` trae nombres, restringe la corrida a esos archivos. Sin ningún `.json` → `FileNotFoundError` accionable. `QTRANS_INPUT_FILES` vacía = sin selección (igual que omisa).
- La CLI hereda todo de `.env` (`load_dotenv(PROJECT_ROOT/".env")` al importar `qtrans.core`); los flags explícitos siempre vencen a los defaults de entorno.
- `--json-out <ruta | ->` (opcional): vuelca el reporte de la corrida como JSON — `run_pipeline` añade `summary["algorithms"]` (por algoritmo: `name`, `display_name`, `input_file`, `url`, `offset`, `qasm: {version, path, code}` = **el circuito OpenQASM completo**, `quirk_capture`, `qasm_image`, `comparison_doc`, `composer_image`, `migrated_scripts`) y, si se pidió, `summary["json_report"]`/`summary["json_report_path"]`. Con una ruta escribe el archivo (`_build_run_report` convierte rutas a `str` y `errors` a `{"stage","message"}`); con `-` la CLI imprime **solo el JSON** en stdout (silencia prints de estado y verbose). Ejemplo restringido a un archivo: `python -m qtrans --input-mode batch --input-file "" --input-files popular_algorithms.json --json-out -`.
